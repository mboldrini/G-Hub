### PR Cards — Expand Panel

- Panel max-height increased to 360px with scroll
- PR body and comment text are rendered as Markdown via **marked.js** (CDN), with a plain-text fallback

#### Expand button reliability fix

- Root cause identified: `detail.style.display` reads only inline styles; the initial `display:none` comes from CSS class, so `element.style.display` returned `''` instead of `'none'`. This caused the first click to enter the "collapse" branch and do nothing visible — requiring 2+ clicks to open.
- Fixed by tracking open state on the button itself: `btn.classList.contains('expanded')` instead of reading `detail.style.display`
- Also replaced the earlier double `requestAnimationFrame` approach with `setTimeout(fn, 30)` for spinner reliability in WebView2

---

### Comments Section

- Previously only the body of the most recent issue comment was stored and shown; the section appeared empty when comments came from review submissions
- Root cause: GitHub review bodies (submitted via "Submit review" dialog) live in `reviews.nodes`, not `comments.nodes`; the `body` field was not being fetched in either GraphQL query; and `ReviewRequestedPrs` only fetched `comments(last: 1)` with no `reviews` field at all
- **Fixes applied:**
  - Added `body` field to both `MyOpenPrs` and `ReviewRequestedPrs` review nodes
  - Added `reviews(last: 5)` with `body` to the `ReviewRequestedPrs` query (was missing entirely)
  - Increased `comments(last: 1)` to `comments(last: 5)` in `ReviewRequestedPrs`
  - Added `Body` property to the `Review` model; `ParseReviews` now parses it
  - Both `MapMyPr` and `MapReviewPr` now merge issue comments + review bodies (non-empty, non-bot), sorted by timestamp descending
- New `PrCommentDto` class (Author, Ago, Body) exposed on both `PrDto` and `ReviewPrDto` as `Comments: List<PrCommentDto>`
- Comments displayed newest-first with author badge and relative timestamp
- If a PR has more than one comment, a **"+ N mais"** toggle appears below the first to expand/collapse older ones
- `renderComments()` and `toggleMoreCmts()` JS functions added
- i18n: `lastCmt` label renamed to **Comentários** / **Comments**; added keys `moreCmts` and `hideOlder`

### PR Tag / Expand Panel Discrepancy Fix

- The PR tag in the list showed the last commenter as one user, but the expanded panel showed a different user
- Root cause: APPROVED reviews with an empty body were being filtered out by `!string.IsNullOrWhiteSpace(r.Body)`, causing them to be excluded from the panel while the older review with body text showed first
- Fix: APPROVED, CHANGES_REQUESTED, and DISMISSED reviews are now included even with empty body; they display a state label (`*aprovado*` / `*approved*`, etc.) as their body text
- New `ReviewStateLabel()` private method generates the localized italic label per state

---

### Expand Panel — Column Layout Fix

- Description column was significantly wider than the Comments column in the two-column expand panel
- Root cause: `1fr 1fr` in CSS Grid does not constrain the minimum item size; content overflow caused one column to grow beyond its share
- Fix: changed grid template to `minmax(0,1fr) minmax(0,1fr)`, which forces minimum to 0 and guarantees a true 50/50 split
